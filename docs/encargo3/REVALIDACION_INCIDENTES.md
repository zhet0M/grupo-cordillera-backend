# Revalidación de los 21 incidentes heredados

Revisión: 8 de noviembre de 2026. Fuente original: Encargo 2, sección de incidentes, páginas 23–24. Se mantienen sus IDs y severidades históricas como referencia; no se clasifican automáticamente todos como vulnerabilidades. Esta revisión combina código actual y resultados ejecutados el 6 de noviembre. La suite global se repitió el 8 tras restablecer Docker; no se presenta esa corrida como nueva ejecución de las 311 pruebas Java.

**Corregido y verificado** significa que existe cambio específico y evidencia posterior. **Abierto** conserva el defecto observado o el contrato sin resolver. **Parcial** indica mitigación acotada. **Aclaración** identifica comportamiento de diseño o ambigüedad que requiere decisión; no equivale a aceptación por parte del dueño del producto.

## Hallazgo adicional INC-22: configuración heredada de despliegue

Origen: revisión estática del 8 de noviembre de api-gateway/docker-compose.yml. El Compose original conserva contraseñas PostgreSQL de desarrollo fijas y publica puertos de bases y servicios de dominio. No se inició ese Compose ni se probó acceso desde otra máquina. La exposición efectiva depende de enlaces de red, firewall y entorno; no se afirma explotación demostrada.

Prioridad propuesta: alta de configuración antes de cualquier despliegue compartido. El laboratorio docker-compose.qa.yml utiliza credenciales externas y no publica bases ni servicios de dominio, pero esa mitigación está limitada a QA y **no corrige el Compose original**. Alternativas: externalizar todas las credenciales de bases, rotar las usadas, limitar enlaces de host a loopback cuando sean necesarios o retirar publicaciones y restringir la red interna. Cierre: revisión de configuración efectiva sin imprimir secretos, pruebas de conectividad autorizada/denegada y validación de despliegue. Responsable propuesto: desarrollo y operaciones. Estado: abierto. No se modifica infraestructura heredada en este bloque documental.
